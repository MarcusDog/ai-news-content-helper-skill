# Evidence and anti-filter-bubble rules

## Evidence types

| Type | Suitable for | Required boundary |
| --- | --- | --- |
| Official | Release facts, documented features, company position | A claim by the interested party is not independent proof |
| Research | Methods, measured results, scientific limitations | Check sample, baseline, peer review, and replication status |
| Media | Context, interviews, industry reporting | Attribute the report; verify key numbers against primary material |
| Engineering/community | Implementation experience and edge cases | A case study may not generalize |

## Source selection order

1. Original release, specification, repository, filing, or official documentation.
2. Paper, benchmark, dataset, or independent technical evaluation.
3. Reputable reporting that provides context or interviews.
4. Engineering/community material that reveals real-world constraints.

Use a secondary source to widen perspective, not to replace an available primary source.

## Diversity gate

A brief is ready when it normally has:

- 3–8 items from at least 3 publishers;
- at least 2 evidence types;
- both domestic and international coverage when relevant;
- no publisher contributing more than 2 selected items;
- a limitation, dissenting view, or explicit unknown for strong claims.

Do not chase numerical balance when a topic legitimately has only one authoritative source. Explain the structural limitation instead.

## Citation style

Write: `该版本新增本地推理支持 [S1]。`

For attribution: `据某媒体报道，部分商家正在测试该功能 [S2]。`

For inference: `综合官方路线图与两项工程测试，可以推测部署门槛正在降低 [S1][S3][S4]；这是推断，不是已证实的行业结论。`

Never write a URL-less source label such as “据报道” or “有论文称”.

## Conflict handling

When sources disagree:

1. Present both claims with separate citations.
2. Compare date, definition, sample, and incentives.
3. State which evidence is stronger and why.
4. Avoid manufacturing a false midpoint.
